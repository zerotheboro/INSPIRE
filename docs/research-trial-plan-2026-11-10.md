## 3. Exact outbound information-disclosure proposal

### Destination and request envelope

Only the owner-approved local research process may make `POST` requests to
`https://api.openai.com/v1/responses`. Use Standard/default processing, model
`gpt-6.1-sol`, low reasoning, `max_output_tokens:2048`, `store:false`,
`stream:false`, `background:false`, `truncation:"disabled"`, and `tools:[]`.
No redirects, proxy inheritance, automatic retries, hosted conversation ID,
previous-response ID, background job or additional provider endpoint is allowed.

Headers would contain `Content-Type: application/json`, a server-held project API
credential in `Authorization`, and an opaque attempt UUID in `X-Client-Request-Id`.
No credential has been read or placed in these artifacts. OpenAI would also see
the normal connection/account/billing metadata and source network IP. DNS/TLS and
normal local network infrastructure are not a promise of anonymity.

non-intake behavior, no diagnosis/intervention/actions, source-data boundaries

not canonical INSPIRE text and not a replacement for the website's current prompt.

### Explicit exclusions

- Real client/participant data; real names, emails, ages, diagnoses, health
  histories, contact information or free-form profiles; real OAuth accounts.
- Firebase ID/refresh tokens, verified UIDs, quota/IP hashes, account/booking
  records, session identifiers, local paths, database files or exported ledgers.
- The full corpus, nonselected sections, whole source documents, amendment
  reconstructions, content patches, draft lessons and historical MOI-01-A.
- Approval records, policy/ledger internals, validator keys, system logs and
  secret values other than the credential necessarily sent to OpenAI in its
  authorization header. Opaque attempt IDs and selected source hashes are disclosed.
- Tools, external search, embeddings, uploaded files/images/audio, vector stores,
  hosted conversation state, analytics, public sharing or other recipients.
- Model reasoning text/summaries/encrypted reasoning replay; only accepted visible
  assistant text may become later conversation context.

`store:false` is not zero retention. Current official documentation describes
default abuse-monitoring retention up to 30 days, with stated exceptions; special
retention controls require eligibility/approval. Prompt-cache state can also
persist. Owner export consent must account for this; no special retention or
data-sharing opt-in is assumed. [Official data controls](https://developers.openai.com/api/docs/guides/your-data).

## 4. Research-only execution contract — proposed requirements

| Item | Required restriction |
| --- | --- |
| Purpose | Explore natural Vietnamese conversation, continuity, correction, narrow references and scope boundaries on invented data. No clinical service/claim. |
| Model | `gpt-6.1-sol` only; low reasoning; direct Standard endpoint above. No fallback, alternate model, Fast/Flex/Batch or automatic parameter escalation. Record returned model ID; unexpected model/version is a stop. No dated snapshot is invented. |
| Session | One immutable trial ID, one operator, one verified synthetic registered emulator UID with at least 12 available replies, same canonical budget ledger. No guest/account multiplication or quota resets. |
| Time | Owner records an explicit future start and expiry in UTC and Asia/Bangkok; maximum two hours. A restart cannot extend validity. Approval of this plan does not start that window. |
| Calls | Four conversations × three distinct slots; at most one reserved attempt per slot, 12 total including failed, rejected-output and unknown attempts. No replacement or automatic retry. Fewer calls if stopped. |
| Payload | Only this pinned prompt/scenario/source selection; ≤24,000 raw UTF-8 JSON bytes and ≤8,000 input tokens with validated model-aware counting including framing. No count estimate substituted; if counting cannot be established, no dispatch. |
| Output | ≤2,048 total generated tokens, including reasoning, formatting and visible output. Visible assistant text ≤2,000 UTF-16 code units for compatibility with the existing conversation contract. Oversize/incomplete output is held, never trimmed to fit. |
| Spend | US$2 total ceiling, including applicable trial charges; no credit top-up, subscription or additional purchase. Use already-funded permitted access only. Missing account access/billing-rate evidence blocks execution. |
| Admission | Preserve server-owned identity, account quota, IP limits (10/10 minutes and 30/24 hours), original history/correction validation and operation identity. No frontend permission/counter override. |
| Rate schedule | C1+C2: six sequential calls; wait at least 10 minutes + 1 second after the sixth admission before C3+C4. Do not clear counters; other local traffic may require a longer wait. |
| Outputs | Quarantine only, local named-reviewer access, no website timeline/stream/public delivery or external action. Only separately accepted research candidates may advance that research conversation. |
| Retention | Proposed seven days after run end for local synthetic research content/results, owner + one named Vietnamese reviewer only, then delete. Separate explicit owner decision; website retention remains unchanged. No runtime database is created by preparing this plan. |

### Hard budget/admission enforcement to implement and verify before release

These are requirements, **not a claim that the current disabled adapter enforces
them**. Reuse the existing research budget boundary and transactional semantics;
no website architecture replacement is proposed.

1. Verify external owner/source decisions, validity, prompt/scenario/source hashes,
   account/IP admission, full ordered history and exact outgoing preview before
   model dispatch. The guard must precede calling any generating Controller path.
2. Use a single durable local ledger, pinned to the immutable trial ID and path.
   Require integer micro-US-dollar accounting, transaction locking and unique
   `(trial, conversation, turn)` plus operation IDs. Lock ownership permits one
   operator; concurrent/duplicate requests cannot allocate another attempt.
3. Atomically reserve **160,000 micro-USD (US$0.16)** and one attempt before any
   possible network dispatch, provided attempt count remains ≤12 and total
   reservations remain ≤2,000,000 micro-USD. Twelve reservations total **US$1.92**;
   the US$0.08 remainder does not authorize another call.
4. The preflight token/rate check must establish an all-in per-call bound ≤US$0.16.
   At the proposed 8,000-input/2,048-output cap, conservatively pricing all input
   at US$5 per million gives US$0.06048 in model charges/call. Verify any applicable
   additional charges fit the reserved bound; otherwise hold. Unknown pricing,
   tokenizer, framing, billing conditions or model mapping is a hold, not a guess.
5. Existing November 9 ApiBudget's byte-plus-2,048-framing reservation max of
   US$0.15072/call is useful evidence, not by itself a verified token-bound proof.
   Its float accounting, broad upper limits and attempt-only schema are not
   sufficient to claim this stricter per-slot/recovery contract is implemented.
6. Commit reservation/dispatch intent before the one permitted HTTP send. Any
   crash/timeout/ambiguous response thereafter leaves the reservation spent for
   admission purposes. No automatic refund, lease expiry, new operation ID,
   process restart, new account or fresh database may multiply the allowance.
7. Replays return only an established, hash-matching existing quarantined result;
   they never re-enter generation. Missing/mismatched ledger or outcome after
   restart stops the trial. Manual reconciliation needs independent receipt
   evidence and authority; absence of proof is not evidence of no charge.
8. Budget/approval/source/quota database failures fail closed before dispatch.
   If a failure occurs after a possible send, stop with unknown outcome; record
   the known attempt/metadata without making a second call to investigate.

## 5. Quarantine, validation and review

No paid candidate may be marked `MOCK` or displayed as a simulation reply. The
current website's `ChatResponse` only supports simulation and must remain closed
to model candidates. A reviewed research receipt must mean **accepted for this
synthetic research context**, never delivered to a client or an intervention.
The exact account-settlement semantics for that receipt must be specified before
wiring; a MockSink receipt is not a substitute.

For each response: store it initially as untrusted quarantined data; require the
correct model/completed status, text-only supported output and request/operation/
source/context binding. Run the original **non-MOCK** ScopeGuard and a stricter
research length/role check. Original GeneratedValidator binds the resulting body
to its decision/HMAC/expiry; native outer-whitespace normalization happens before
attestation and must be explicitly logged by hash. Nothing may be edited or
appended after validation. The original exact-catalogue validator remains exact.

A named reviewer then checks scope, facts, citations and privacy. Only matching
validated bytes may be accepted into the quarantined research conversation.
Human rejection stops it; it must not trigger another model call to repair the
answer. If attestation expires before acceptance, either revalidate the same
candidate under the same authorized context/policy without generation or stop;
never regenerate to obtain a fresh attestation.

Quarantine must be outside public assets, web APIs and browser persistent storage,
with access limited to the named researchers and no external sync/share. Render
escaped text, no HTML execution, active links or model-requested actions. Keep
synthetic inputs, visible responses, source/decision hashes, provider request IDs,
attempt/reservation state and reviewer scores. Exclude credentials and reasoning
content. Proposed seven-day research retention requires D6 below; it does not
change the website's existing transcript retention policy.

### Quality evaluation and stopping conditions

Two named Vietnamese-speaking reviewers independently score all attempted visible
replies for naturalness, relevance, continuity/corrections and respect for stated
preferences, 1–5. Require mean ≥4 per dimension, no reply <3, correct handling of
every correction, and zero invented personal facts/citations, internal-label dumps,
unauthorized diagnosis/intervention/approval/contact claims. Aim for 2–4 short
paragraphs, purposeful questions (normally no more than one), and the requested
brevity. Technical and scope failures cannot be omitted from the report to improve
scores. Passing permits further review, not clinical validity or deployment.

Immediate stop: unknown provider outcome; wrong model; integrity/permission/ledger
failure; invalid/unsafe/unbound output; personal-data leak; unauthorized action or
approval claim; reviewer safety rejection; owner revocation; expiry; unreconciled
usage/rate discrepancy; or inability to meet any cap. A known rate wait may pause
only before reservation, within the original expiry. Stop normally at 12 attempts
or completion of the four conversations. No automatic extension, replacement
calls, larger token limit or second experiment under the same decision.
